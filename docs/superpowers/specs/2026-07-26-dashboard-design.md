# DNS 仪表板设计规格

## 目标

为 dnsbuffer 增加一个随主进程运行的 Web 仪表板，持久化并展示 DNS 查询趋势、上游性能、域名排名和查询明细。功能必须保持现有单可执行文件部署方式，且统计故障不得影响 DNS 查询服务。

## 范围

仪表板展示以下数据：

- 查询趋势折线图：总体查询数、被广告规则屏蔽的查询数、缓存命中数。
- 每个主上游及后备上游的滑动窗口平均成功请求耗时。
- 域名查询次数前 20 名，以及每个域名的总次数、屏蔽次数和缓存命中次数。
- DNS 查询明细，包括时间、域名、查询类型、响应状态、总耗时、屏蔽标记和缓存命中标记。

本次不保存客户端 IP，不提供身份认证、运行配置修改、数据库导出或管理操作。

## 配置

新增可省略的 `[dashboard]` 配置节：

```toml
[dashboard]
listen = "0.0.0.0:8080"
database_path = "dnsbuffer.db"
retention_days = 7
```

- `listen` 默认为 `0.0.0.0:8080`。
- `database_path` 默认为 `dnsbuffer.db`。相对路径以进程工作目录为基准，也支持绝对路径。
- `retention_days` 默认为 7，`0` 表示永久保留。
- 无效监听地址、空数据库路径或无法表示的保留天数必须在配置加载或服务启动阶段返回明确错误。
- 服务无认证且监听全部网卡，文档必须提示仅在受信任的局域网内使用，并建议通过防火墙限制访问。

## 总体架构

新增独立的 `dashboard` 模块。它包含统计事件模型、SQLite 存储、HTTP API、上游统计快照和嵌入式前端资源。DNS 查询管线仅负责生成统计事件，不直接执行数据库操作。

程序启动顺序如下：

1. 加载并校验配置。
2. 初始化 SQLite 数据库、表结构、索引和保留期清理。
3. 构建查询管线和共享的上游统计快照源。
4. 启动数据库工作线程和 HTTP 服务。
5. 启动 UDP DNS 服务。

HTTP 服务启动失败视为启动失败，避免进程看似正常但仪表板不可用。DNS 服务与 HTTP 服务并行运行；任一关键服务意外退出时，主进程返回错误。

## 查询采集

`Pipeline::handle` 为每次格式正确且至少包含一个问题的客户端查询记录开始时间，并在产生最终响应后构造统计事件。事件字段为：

- UTC 时间戳。
- 规范化域名，去除结尾根标签点并统一为小写。
- DNS 查询类型。
- 最终响应码，如 `NOERROR`、`NXDOMAIN`、`SERVFAIL`。
- 查询总耗时（毫秒）。
- `blocked`：是否被广告规则屏蔽。
- `cache_hit`：是否命中缓存，包括过期缓存的乐观命中。

语义约束：

- hosts 本地响应计入总体查询，不计入广告屏蔽或缓存命中。
- 广告规则命中的查询标记 `blocked = true`，并记录实际响应码。
- 缓存命中标记 `cache_hit = true`；后台缓存刷新不是新的客户端查询，不写入查询明细。
- 上游成功、上游返回非成功响应及最终 `SERVFAIL` 均记录最终响应码和总耗时。
- 客户端响应发送失败不撤销已处理查询的统计。
- 不保存客户端 IP。

统计事件通过有界通道发送给专用数据库工作线程。发送操作不得等待：通道已满、数据库暂时繁忙或数据库写入失败时丢弃该统计事件并输出限频告警，DNS 响应不受影响。工作线程批量处理事件以减少事务开销；进程正常退出时在有限时间内尽力排空队列，不无限等待。

## SQLite 数据模型

数据库启用 WAL 模式和合理的 busy timeout，以降低持续写入与仪表板读取之间的竞争。

### 查询明细

`query_logs` 保存：

- 自增 ID。
- UTC Unix 时间戳。
- 规范化域名。
- 查询类型文本。
- 响应状态文本。
- 非负总耗时毫秒。
- 屏蔽布尔值。
- 缓存命中布尔值。

至少为时间倒序分页和域名排名建立索引。

### 聚合统计

`query_hourly_stats` 与 `query_daily_stats` 分别以 UTC 小时和 UTC 日期作为唯一桶键，保存：

- 总查询数。
- 广告屏蔽数。
- 缓存命中数。

写入单条查询明细及更新对应小时、天聚合桶必须位于同一事务中。聚合使用增量 upsert，趋势 API 不扫描整张明细表。

### 数据迁移

数据库包含 schema 版本。首次启动创建当前结构；未来结构变化通过按版本顺序执行的迁移完成。遇到高于程序支持版本的数据库时拒绝启动，避免破坏新版本数据。

## 保留与清理

启动后执行一次清理，之后每 24 小时执行一次：

- `retention_days > 0` 时，删除早于当前 UTC 时间减去保留天数的查询明细。
- 小时桶按其完整时间范围删除过期数据。
- 天桶只在整天完全早于保留截止点时删除，避免删除仍与保留窗口重叠的当日数据。
- `retention_days = 0` 时跳过删除。

日常清理不执行完整 `VACUUM`，避免长时间锁库。释放页由 SQLite 后续写入复用，因此文件大小不保证立即缩小。

## 趋势统计

趋势默认覆盖范围和粒度由保留配置决定：

- `retention_days` 为 1 至 15：覆盖完整保留窗口，按 UTC 小时聚合。
- `retention_days` 大于 15：覆盖完整保留窗口，按 UTC 天聚合。
- `retention_days = 0`：仅展示最近 30 天，按 UTC 天聚合。

API 根据请求时刻确定固定边界，并为没有查询的桶补零，以保证三条折线连续。响应包含 UTC 起止时间、`hour` 或 `day` 粒度及每个桶的总体、屏蔽和缓存命中计数。前端按照浏览器本地时区格式化标签，但不改变后端桶边界。

## 上游性能统计

继续以现有 `UpstreamStats` 滑动窗口作为调度与展示的单一统计来源。为每个上游公开只读快照：

- 稳定名称，如 `plain:1.1.1.1:53`、`dot:dns.quad9.net` 或 `doh:example.com`。
- 分组：`primary` 或 `fallback`。
- 成功请求平均耗时。
- 失败率。
- 当前样本数和成功样本数。

每次实际上游尝试均更新对应成员统计，包括重试和对冲产生的尝试。平均耗时只计算窗口内成功样本。没有成功样本时 API 返回空平均值，前端显示“暂无数据”，不展示调度代码使用的 100 ms 冷启动中值。

快照读取不得长时间持有成员锁，也不得影响上游选择。现有统计类型需增加轻量快照方法，而不是复制调度逻辑。

## HTTP API

HTTP 服务只提供静态页面和只读 JSON API：

- `GET /`：仪表板页面。
- `GET /assets/...`：嵌入的 CSS、JavaScript 和图表资源。
- `GET /api/dashboard/trend`：趋势范围、粒度及补零后的时间桶。
- `GET /api/dashboard/upstreams`：主、后备上游的滑动窗口快照。
- `GET /api/dashboard/queries?page=1&page_size=50&domain=example`：查询明细倒序分页，可按域名模糊查询。
- `GET /api/dashboard/rankings`：数据库全部现存查询明细中的域名前 20 名。

查询分页默认每页 50 条，最大 200 条。`page` 和 `page_size` 必须为正整数；非法参数返回 `400`。查询结果包含总记录数、当前页、每页条数和记录列表。

可选的 `domain` 参数先去除首尾空白，再对已规范化域名执行不区分 ASCII 大小写的包含匹配。例如 `google` 可匹配 `www.google.com`。空字符串等同于不筛选。筛选条件同时作用于记录列表与总记录数；域名参数设置合理长度上限，超限返回 `400`。查询使用参数绑定并转义 SQLite `LIKE` 通配符，使用户输入的 `%` 和 `_` 按普通字符匹配，不能改变查询结构或匹配语义。

排名以总查询次数降序排列，总数相同时按规范化域名升序，确保结果稳定。每项返回总查询数、广告屏蔽数和缓存命中数。

API 时间使用 UTC RFC 3339。响应使用 UTF-8 JSON 和明确的内容类型。数据库错误返回不泄露路径或 SQL 的结构化 `500` 响应；未知路由返回 `404`；不支持的方法返回 `405`。接口不提供任意文件读取、SQL 输入或配置修改能力。

## 前端

前端采用原生 HTML、CSS 和 JavaScript。图表库以固定版本存放在仓库并在编译时与其他资源一起嵌入 Rust 可执行文件，不使用 CDN，不要求部署环境安装 Node.js 或提供静态文件目录。

页面采用紧凑、偏运维工具的深色视觉：

- 顶部展示服务名称、数据范围、聚合粒度、最后成功更新时间和刷新状态。
- 第一部分展示总体查询、广告屏蔽和缓存命中三条颜色固定且易区分的折线。
- 第二部分展示上游列表，区分主上游和后备上游，并显示平均耗时、失败率和样本数。
- 第三部分展示域名前 20 名及三类计数。
- 第四部分展示查询明细表、本地化时间、状态标签、域名搜索框和上一页/下一页分页。

桌面端充分利用宽屏；移动端采用单列布局，数据表允许横向滚动。可交互元素具备键盘焦点样式，颜色不是状态的唯一表达方式。

页面加载后立即请求数据，此后每 5 秒并行轮询四个 API。新轮询开始前取消或忽略尚未结束的上一轮同类请求，避免慢请求乱序覆盖新数据。查询明细的域名搜索输入采用短暂防抖；搜索条件变化时回到第一页并立即刷新，切换页面或定时刷新时保持当前搜索条件。某一区域失败时保留该区域最后一次成功数据并显示局部错误，不清空其他区域；全局更新时间只反映最近一轮成功刷新。

## 性能与故障隔离

- SQLite 同步操作仅在数据库工作线程或专门的阻塞任务中执行，不占用 Tokio 异步执行线程。
- 写入采用有界队列和小批量事务，容量及批量参数作为内部常量，首版不增加用户配置。
- API 查询使用独立数据库连接并设置超时；慢查询不会持有 DNS 管线资源。
- 域名排名基于受保留策略约束的明细表。永久保留会使排名查询成本随历史增长，索引和查询计划必须在测试中验证；首版不额外维护排名汇总表，避免删除和修正逻辑复杂化。
- HTTP 响应设定合理大小边界，查询明细单页最多 200 条。
- 统计丢失仅影响仪表板准确性，绝不改变 DNS 响应结果。

## 测试策略

### 配置测试

- `[dashboard]` 缺省值。
- 自定义监听地址、数据库路径和保留天数。
- `retention_days = 0` 永久保留语义。
- 非法监听地址及无效数据库配置。
- 示例配置持续可加载。

### 查询管线测试

- hosts、广告屏蔽、缓存命中、上游成功和 `SERVFAIL` 分支产生正确事件。
- 响应码、耗时、查询类型和规范化域名正确。
- 过期缓存命中被标记，后台刷新不产生新客户端事件。
- 统计队列满或接收端关闭时 DNS 响应不受影响。

### 存储测试

- 明细与小时、天聚合在同一事务中更新。
- 数据可在关闭并重新打开数据库后读取。
- 保留期清理边界和 `retention_days = 0`。
- 排名的计数、排序、前 20 限制与平局行为。
- 明细倒序分页、域名包含查询、通配符转义、筛选后总数及索引使用。
- schema 创建、支持版本打开和未来版本拒绝。

### 统计与 API 测试

- 小时/天粒度切换及永久保留最近 30 天规则。
- 空桶补零和 UTC 边界。
- 上游无样本、成功、失败、主组和后备组快照。
- API 成功响应、域名搜索与长度限制、分页参数校验、`404`、`405` 和数据库错误映射。
- 静态资源路由、内容类型和嵌入资源完整性。

### 前端与端到端验证

- JavaScript 数据映射、域名搜索防抖、筛选时重置分页、分页状态和失败后保留旧数据等关键逻辑测试。
- 人工检查桌面与移动端布局、无数据状态、长域名和 API 局部失败状态。
- 运行完整 `cargo test`。
- 使用临时数据库和非特权 DNS 端口启动进程，执行 DNS 查询并验证仪表板 API 和静态页面。

## 文档与部署

README 和示例配置增加仪表板配置、访问方式、数据口径、SQLite 路径及局域网无认证风险说明。Docker 镜像需暴露或在示例命令中映射 TCP 8080，并为数据库文件提供可写持久化卷；distroless 运行环境不需要新增前端运行时。

## 验收标准

- 默认配置启动后可通过 `http://<主机地址>:8080/` 打开完整仪表板。
- DNS 查询在 5 秒内反映到查询列表、排名和趋势图中。
- 查询明细可通过域名片段快速筛选，并正确展示该域名的屏蔽与缓存命中情况。
- 三条趋势线口径准确，并按保留天数选择规定粒度和范围。
- 上游列表展示与调度滑动窗口一致的成功请求平均耗时。
- 查询明细跨重启保留，按配置天数清理；配置为 0 时不清理。
- 不记录客户端 IP。
- 前端无需外部网络和额外静态文件即可工作。
- SQLite 不可用、写入失败或统计队列满时，DNS 查询仍按原有行为返回。
- 完整自动化测试通过，桌面和移动端冒烟验证通过。
